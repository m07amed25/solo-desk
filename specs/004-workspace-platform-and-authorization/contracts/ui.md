# Workspace interaction and localization contract

Extend the existing `/app` surface; internal `[locale]/[theme]` aliases and preference allowlists keep their current public behavior. No broad dashboard, new finance screens or persistent draft store is introduced.

| Component / surface                   | Required behavior                                                                                                                                                                            |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Existing account page / profile       | Preserve `LiveProfile` and `saveProfile`; show workspace selector/create flow beside the personal section; existing profile data remains unchanged                                           |
| `components/workspace-panel.tsx`      | Small interactive boundary for create/select/settings/invite/member actions; active workspace appears above consequential controls, with server-returned allowed actions for visibility only |
| `components/workspace-invitation.tsx` | For authenticated /app, read and immediately remove `/app#invitation` fragment, hold proof only in memory; explicit online Accept after current recipient verification; never auto-accept on GET             |
| Existing SiteHeader                   | Reuse theme/language/sign-out controls; no unrelated navigation redesign                                                                                                                     |
| `emails/workspace-invitation.tsx`     | English and Arabic sections/subject, sender/team/action/expiry and safe accept link; no tracking, remote image or account-existence hint; recipient address is not echoed in public errors   |

Use installed shadcn/Base UI primitives from `components/ui/` and existing Field/Input/Button/Alert/Skeleton/DropdownMenu variants. Add an official Base UI primitive only when an included flow requires it and existing components cannot do the job; inspect provenance first, avoid a design-system fork or new form library. Prefer small composed panels to a new app shell. Keep server-only imports out of the client graph; pass minimal workspace/own-membership projections and bounded message subsets.

State transitions: checking → unavailable OR signed-out OR no-memberships OR selected; selected → switching/submitting → accepted/conflict/rejected/unknown. Switching conceals prior private data, aborts fetches, disposes subscriptions and ignores late responses by generation. Verify new authority before revealing the new projection. Member removal/session denial conceals team data and clears selection; profile remains subject to its own session. Cross-tab selectors are advisory; mismatched command target returns CONTEXT_CHANGED. No unsent mutation moves teams.

Creation uses explicit name/ASCII slug, validated timezone, en/ar language and currency. In Arabic, isolate UUID/slug/email/token-derived control values with `dir=ltr`/`bdi`; do not alter canonical values. Input normalization/errors come from the server contract. Settings never invent legal/tax readiness. Invitation role options follow the confirmed role matrix; no Owner invitation or arbitrary scope field. Pending delivery, accepted membership and inbox delivery have distinct labels.

Errors use stable machine codes resolved through `messages/en.json` and `messages/ar.json`, with identical keys/interpolation. Include all loading/empty/denied/unavailable/rate-limit/conflict/unknown/reauth/final-owner and expiry states; emails use the same reviewed bilingual vocabulary. Async feedback uses live regions without announcing countdown ticks; failure focuses first invalid field/error summary; selection restores meaningful focus. Use 44px action targets, semantic tokens, logical layout spacing, real labels and keyboard controls. Verify both directions in Light/Dark/System, 320 CSS pixels, 200% zoom, reduced motion, screen reader and fluent Arabic review. Existing documented contrast gaps remain open unless actual affected states are verified.

Network failure preserves permitted input only in memory and names reload/closure loss. No token, profile or team draft is written to localStorage/IndexedDB. Sign-out/account change clears private state. If sign-in or preference reload loses invitation proof, the localized recovery is “sign in, then reopen the invitation email”; do not append the token to auth callback URLs or preferences.

Signed-out invitation navigation must be tested before activation: `/app` currently redirects on the server before a protected client component can mount. Replace unauthenticated redirects with an explicit empty fragment (`/sign-in#`) so browsers do not inherit `#invitation` into sign-in. Audit earlier proxy/SDK redirects for the same property. Assert actual Location and final URL in Chromium/Firefox/WebKit and ensure no telemetry/reporting contains proof; a redirect implementation that strips the empty fragment fails this contract. The signed-out result is ordinary sign-in with no token, then reopen the original email. Do not rely on the protected component running before that redirect.
