## Cross-cutting review

Every family uses the primary shadcn/ui design system, scalable module/service/data boundaries, server-only Neon PostgreSQL, Better Auth identity/session checks, current tenant/resource/action authorization and appropriate design patterns. English/Arabic RTL, responsive accessibility, exact money/time, bounded jobs/queries, audit and recovery apply throughout. Offline behavior is limited to eligible drafts after the browser protection/eviction/key gate; no native installer/bridge/database assumption carries forward.

See [architecture](../architecture/overview.md), [patterns](../architecture/design-patterns.md), [decisions](decisions.md) and [roadmap](roadmap.md). Historical implementation claims remain only in the [feature](../features/README.md) and [QA](../qa/README.md) history, not this current planning register.
